## 4. 本轮发现并修复的问题

### BUG-01：旧数据分析地址直接白屏

- 现象：公网直接访问 `/analysis` 时页面为空，控制台提示 `No routes matched location "/analysis"`。
- 影响：旧收藏、外部链接或历史文档中的地址会得到白屏，用户无法自行恢复。
- 修复：增加 `/analysis` 到 `/nongeo` 的兼容重定向。
- 验证：本地真实浏览器访问旧地址后落到 `/nongeo`，非地理分析工作台正常显示；新增浏览器回归测试通过。

### BUG-02：游客可直接进入不可保存的个人设置表单

- 现象：游客导航已隐藏个人设置，但手工访问 `/admin/profile` 仍显示资料与修改密码入口；后端又明确拒绝游客自助写入。
- 影响：形成“页面看似可编辑、保存必然失败”的错误交互，并暴露无意义的共享账号设置入口。
- 修复：增加共享游客账号自助设置路由守卫，游客访问个人设置或其他回退到个人设置的后台路由时统一返回 `/data`。
- 验证：本地真实浏览器确认 `/admin/profile` 返回数据目录，修改密码入口不再出现；新增浏览器回归测试通过。

### BUG-03：既有底图恢复改动阻断 TypeScript 门禁

- 现象：`MapCanvas.tsx` 保留了已被新恢复决策函数替代的未使用导入，`tsc` 报 TS6133。
- 影响：发布前类型检查失败。
- 修复：只移除该未使用导入，不改变底图逻辑。
- 验证：TypeScript 全量检查和生产构建通过。

## 5. 待确认或基础设施项

### 已解决：普通用户生产权限与代码内置基线不一致

原审计发现生产“普通用户”组拥有数据新增、修改、删除、导出、自定义符号化、AI 解读、栅格管理以及多项后台概览权限，因此测试账号会显示“后台管理”和“数据导入”。代码内置普通用户基线仅包含浏览、查询、加载图层以及查看工程、专题和成果。

经用户确认后，已先保存 25 项变更前快照，再通过生产管理 API 将普通用户组定向收敛为 7 项代码基线权限。重新登录验证表明越权能力和入口均已消失，8 项授权数据、图层快速加载及 2 项已发布专题图仍可用；其他角色未被本次修改。完整证据和回滚清单见 `2026-08-05-ordinary-user-permission-remediation.md`。

### P2：测试账号角色不纯

平台管理员测试账号同时属于“平台管理员”和“科研用户”，实际权限是两组并集。功能测试按真实有效权限完成，但它不能完全代表纯平台管理员基线。建议后续准备只属于单一角色的验收账号。

### P2：游客当前无公开数据资源

游客能查看 2 项已发布成果，但数据目录和地图中公开资源数为 0。界面空态与权限提示正确，因此不是前端异常；如平台预期游客能浏览公开原始数据，需要由管理员选择资源并配置公开可见范围。

### P2：公网 HTTP 导致安全响应头失效

每次页面加载都会出现浏览器警告：非可信 HTTP Origin 下 `Cross-Origin-Opener-Policy` 被忽略。当前业务流程未受影响，但正式发布建议配置 HTTPS 并复核安全响应头。该项涉及域名、证书和网关配置，本轮未改动。

### P3：格式化基线债务

全仓品牌与 lint 检查通过，但格式检查会扫描历史 Playwright 产物并报告 176 个前端文件；后端 Ruff 格式检查报告 50 个既有文件。为避免批量改写用户工作树，本轮未自动格式化。Ruff 规则检查通过。

### P3：天地图限流测试曾出现一次瞬态失败

第一次与后端测试并发运行前端单元测试时，`Retry-After` 用例出现一次异步拒绝；该用例单独重跑、天地图测试文件全量重跑以及前端 41 文件全量重跑均通过，未能稳定复现。建议在 CI 中继续观察重复运行结果。
