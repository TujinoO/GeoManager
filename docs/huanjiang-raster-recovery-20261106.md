# 环江油田影像缺块修复

日期：2026-11-06。范围：工程恢复、保存的栅格引用及环江油田工程25、草稿专题图26。

## 根因

工程“环江油田LUCC结果”的32个栅格包含16个分类解译块和16个原始影像块。第一行第二列解译块仍引用资源158、数据集43、图层142；资源158及对应图层已删除，数据集43保留为无资源关联记录。重新导入的有效数据为资源159、数据集44。

实际读取旧、新两份原始文件，SHA-256均为 `042139e0a301f733d398914890ceb050ad046defab34ae83861e9a055c60d15c`；空间范围一致。原始文件和预处理COG存在，问题发生在保存的引用和显示服务。

另一个问题是保存的样式哈希包含预处理文件指纹和渲染器版本。前端只把瓦片URL的`rv`参数改成当前值，不能更新样式哈希。原恢复流程仅升级旧分类栅格，影像与连续栅格仍可能请求旧哈希，服务器返回404。HTML 404又被错误描述为服务器内部错误。

## 源码修复

- 恢复每个栅格前，通过现有profile接口核验当前数据；重新调用已有异步渲染接口登记保存的规则并等待就绪。分类栅格沿用后端完整静态金字塔及其缓存复用，颜色计算仍在后端。
- 仅在profile返回404、保存的数据集为无资源关联记录、有完整SHA-256且存在唯一就绪候选时恢复重新导入引用。候选须具有相同原始文件SHA-256、栅格类型和完整经纬度范围，并经profile接口再次确认数据集、校验值及访问权限。按名称匹配、多个候选、403、缺失校验值均不自动关联。
- 栅格清单每次恢复按需请求一次；所有新引用进入恢复后的图层状态，后续保存可保存新引用。恢复失败保留可重试的图层状态，停止暴露旧瓦片地址。
- 有自定义符号化权限时保留保存的样式与透明度；其他账号通过现有默认规则渲染接口恢复。没有扩大后端授权。
- 资源404使用明确文案。无API契约、后端权限、TOML根路径、数据格式或迁移变化；使用现有生成客户端与类型。
