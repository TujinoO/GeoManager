# 天地图瓦片请求调度

地理工作台中的天地图矢量底图由 `vec_w` 和 `cva_w` 两组瓦片共同组成。两组 source 共用同一个浏览器端请求调度器，避免分别提速后叠加成不可控的瞬时请求峰值。

## 当前策略

- 正常状态下，请求启动间隔为 100 ms，最多同时保留 6 个未完成请求。
- 收到 HTTP 429 时，调度器立即按照服务端 `Retry-After` 或现有指数退避时间暂停整个共享队列。
- 每轮新的限流会把启动间隔逐级调整为 200、400、600 ms，并把并发数逐级降到 3、2；600 ms 和 2 并发是保护下限。
- 同一冷却窗口内由多个在途请求返回的 429 视为同一轮突发，只延长必要的全局暂停，不重复降低并发和速度。
- 冷却结束后，每连续成功加载 16 个完整瓦片恢复一级：启动间隔减半直至 100 ms，并发数每级增加 1 直至 6。
- 只有响应体成功读取后才计为成功；取消、网络错误、403 和其他失败都不能触发恢复。

该策略只控制浏览器到天地图的请求启动节奏，不改变天地图 Key、域名白名单、日额度、Mapbox 样式切换、业务图层或后端接口。

## 调参边界

调整参数前应在真实页面记录首次可用时间、当前视野完整时间、429 数量和典型瓦片响应时间。不要只提高 Mapbox GL 的图片并发上限；自定义调度器才是天地图两组瓦片的最终入口，两处并发限制必须保持一致。

如果正常网络下长期没有 429，但加载仍慢，优先根据瓦片响应时间判断：高延迟场景可谨慎增加并发，低延迟场景才适合缩短启动间隔。如果出现连续 429，应保留自适应退避并检查天地图控制台的应用额度、域名限制和服务状态，不能用持续固定提速规避上游限流。
