## 性能和稳定性

1. **天地图调用修复**：生产服务器上游返回 HTTP403 / `301012`（权限类型错误），带平台 Referer 同样失败。原出图逻辑把浏览器类型 Key 交给服务器代理；现在天地图保留三维地图的浏览器源、自定义节流 provider 和浏览器缓存。矢量/影像及注记分别保留，不替换用户选择的服务。源未准备好时明确报错；`301012` 归为凭据错误，停止无意义重试。已有网络退避、节点恢复和并发上限保留。
2. **服务器瓦片缓存**：Mapbox 出图继续走平台代理；相同瓦片合并在途请求，完整写入后原子替换缓存。失败退避3秒、最多512个失败键，校验真实图片，超时和写盘错误归一为既有503响应。缩略图原有降级保留；正式出图缺真实瓦片仍失败。
3. **预览调度**：防抖160→450ms，在途地图完成后再处理最新编辑，复用四张图像缓存。关闭/正式导出取消预览，正式导出期间禁用刷新。大GeoJSON的样式签名每次合成只序列化一次。
4. **渲染与输出**：剔除隐藏层、范围辅助层及无引用源；设备DPR补偿避免高分屏重复扩大framebuffer。透明空画布不能被保存为成功的PNG/JPEG。
5. **内容及传输**：JSON/GeoJSON启用GZip。内容卡片用 `summaryOnly=1`，不读取正文、内部备注和附件/链接列表，详情再读取。受控附件使用 `private,no-cache` + ETag；复用前仍校验可见性和登录状态。
6. **展示图下载量**：11张图片制作WebP展示副本，原图保留；19,221,326→3,294,220 bytes，减少82.9%。这是所选图片传输量变化，不是整站提速比例。登录页只加载当前、退出中、下一张背景。来源、尺寸和哈希见 `portal-image-optimization.json`；缩略对照已目视检查。
7. **服务并发配置**：默认值和Docker示例的Waitress线程数改为8。生产TOML当前显式设为2，代码默认值不会覆盖它；部署时需要同步，并复测CPU、内存和响应时间。

## 内容样例与操作

清单：`backend/apps/content/seed_data/articles.json`。科普四类各两篇，共八篇：四篇发布、两篇待审核、两篇草稿；新闻五篇发布，其中一篇置顶。六张真实配图及来源/哈希在同目录 `provenance.json`。七个用户提供链接均已覆盖，同一获奖事件的学校报道、新华网和海报合并为一篇，保留2022/2025/2026原报道日期。正文为平台导读，不整篇复制新闻；科普方法样例不写成平台已获得的科研成果。

### 导入

在加载目标TOML的后端环境执行，owner须为已有有效内容管理员：

```powershell
pixi run python manage.py migrate
pixi run python manage.py seed_platform_content --owner <已有内容管理员> --dry-run
pixi run python manage.py seed_platform_content --owner <已有内容管理员> --publish
```

省略 `--publish` 时全部作为草稿；带参数按清单分别发布/待审核/草稿。按seed_key跳过已有样例，不覆盖编辑修改，不替换历史内容。导入记录审计；应用启动时不自动导入。

### 维护链路

1. 从“胡杨科普→科普更新”或“关于我们→团队动态”进入。
2. 新建标题、分类、摘要、正文、日期和资料链接，先保存草稿；编辑窗保留，可继续上传图片、设封面、写图注并再次保存。
3. 设为“待审核”。管理员核对正文、图文对应和来源后改为“已发布”；需要修改则回草稿。
4. 已发布科普出现在栏目及原科普页更新区；新闻进入动态页。下架后普通用户不可读正文或图片，条件缓存仍经过权限检查。

审核沿用core.manage_auth，没有新增独立审核角色或强制作者/审核者分离。状态变化记审计，送审和发布拒绝空标题、分类、正文。
